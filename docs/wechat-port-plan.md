# 微信版落地盘点（2026-11-12）

> 目的：把「微信版提审包」拆成能做的和卡住的，别让资质问题挡住能先干的技术活。
> 结论先行：**真正的门槛不是资质，是 UI 层的 DOM 依赖**——这一步没定，工程壳做了也跑不起来。

## 一、已经有了什么

| 层 | 状态 | 位置 |
|---|---|---|
| 关系链上报 | 已完成：`wx.setUserCloudStorage` 写 6 个 KV（层数/用时/誓约/结局/塔印/回响） | `js/wxbridge.js` `submit()` |
| 好友榜读取 | 已完成：`getOpenDataContext().postMessage` + `wx.onMessage` 收回影子 | `js/wxbridge.js` `request()/onFriends()` |

| 异步竞争闭环 | 已完成：好友影子并入「贴码进榜」同一份存储，榜单不依赖平台 | `localStorage.towermates_rivals` |
| 挑战码 | 已完成：贴码进榜、分享图、二维码 | `js/challenge.js` + 根目录分享图 |

也就是说：**社交数据链路已经写完了，而且是可降级的**（没有微信环境时走挑战码，闭环不塌）。

## 二、硬缺口（按阻塞强度排序）

1. **UI 层 100% 依赖 DOM**（最大缺口）。当前 3400 行 `main.js` 里所有面板、HUD、对白、
   商店、结算都是 DOM 节点 + CSS 动画；小游戏环境没有 `document`，一行都跑不起来。
   只有 Canvas 那层（`render.js`）能直接复用。
2. **没有小游戏工程壳**：缺 `game.json` / `project.config.json` / 小游戏入口 `index.js`（现在入口是 `index.html`）。
3. **缺开放数据域子域**：好友榜要在子域里用 canvas 画到 `sharedCanvas`，这份代码现在只有「请求/回传」的协议，没有绘制实现。
4. **主体与资质**：小游戏需企业/个人主体 + 游戏自审报告；IAA 无需版号（已写死 IAA，红线 A 级）。

## 三、两条路线（必须先选，其余都跟着它走）

| | A · 小游戏（原生） | B · 小程序 + web-view 嵌 H5 |
|---|---|---|
| 改造量 | UI 层重写成 canvas 自绘，估 3–5 天 | 近乎为零，现有 H5 直接塞 |
| 关系链 | 可用（开放数据域、托管数据） | **不可用**（web-view 里拿不到小游戏能力） |
| 性能 | 好 | 一般（web-view 多一层） |
| 提审 | 小游戏类目 + 自审报告 | 小程序类目，web-view 需域名白名单与业务域名校验 |
| 结论 | 想要社交红利就走这条 | 只想「微信里能玩」就走这条 |

**建议**：先按 B 走一版「微信里能打开」，把玩家引进来验证留存；留存站得住再投 A。
理由：EXP-01 里关系链红利（7 留 +22%）只在**有量**时才兑现，没量的关系链是零。

## 四、提审前可以先干的技术项（不依赖资质）

- [ ] 把 `render.js` 与 `main.js` 的边界再切一刀：抽出「画什么」与「怎么交互」，为 A 路线留接口（半天）
- [ ] 开放数据域子域的榜单绘制实现（纯 canvas，可先在 H5 用同一份代码画调试）(1 天)
- [ ] 小游戏工程壳骨架（`game.json` 只需 `deviceOrientation` + `showStatusBar`，半天；没有 A 路线决策就先不建）
- [ ] 首次进入的微信环境探测与降级提示（已由 `WXBridge.available()` 覆盖，无需改动）

## 五、卡在资质/外部凭据（待决策区 ②）

- 主体类型（企业 / 个人）：影响可申请的类目与支付能力
- 游戏自审报告：需要玩法说明、内容自查表、截图
- 若走 B 路线：web-view 业务域名需备案主体一致

## 六、本轮结论

「微信版提审包」这条待办**不能整体推进**——它卡在路线选择上，而路线选择取决于你想先验证什么
（社交红利 vs 微信内可玩）。已把可做的技术项拆出来（第四节），其余等路线定了再动。
